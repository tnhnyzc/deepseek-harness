# Agent Note: desktop stage 8 — session and event correctness: close deferral, inspect arming, correctness suite

Status: implemented

English | [中文](2026-08-26-desktop-stage8-correctness.zh.md)

## Problem

Stage 8 (SPEC §22) must prove that Desktop preserves the pinned DSH event-log semantics exactly — no event lost, duplicated, reordered, or fabricated — across bursts, cancellation, and renderer reload. Stage 6's parity pass surfaced three findings that had to be resolved at their correct seams before that proof would mean anything:

1. **Stale title on the cold list after a rename.** The user rename is a durable `session/title` event, but the projection cache that feeds the cold list's title hint could lose the write carrying it: the parity flow restarted into the old checkpoint title.
2. **Cold-start inspect-sync transient.** One `[cordis-client-runner] syncing inspect providers failed: … no active Connection` console error on cold boot that the parity gate had to special-case.
3. **Transport channel replacement.** The broker replaces the channel on re-open; Stage 6 could not exclude that a replaced channel misdelivers a stale in-flight response.

The carrier-only rule is strict: a shared DSH defect gets a DSH-seam fix (shared with `dsh web`), never a desktop-side workaround, and the Desktop carrier packages stay untouched (the stage 4 carrier set M1–M3 is unchanged; the fixes themselves become the new shared fork-delta set U1–U3, accounted in `apps/desktop/docs/upstream-contract.md`).

## Decision

**Finding 1 — four root causes, one bounded close-deferral contract.** Tracing the parity failure end-to-end (a file-gated instrumented run showed the drain's final write failing `unit 'session_projcache' is closed` *after* the cut was already correct) settled four independent causes: A — the storage facility `closeAll` closed domains in parallel with the owner's `close()` drain, so the drain's final put raced the unit close (`packages/storage/storage-domain/src/index.ts`); B — `session-projection-cache` started a fresh store per `write()`, so two in-flight stores of one session interleaved read-modify-put and an older write could clobber a newer one; C — the rename cut was registered late, so a write admitted before the cut could still store after it and resurrect the old title; D — the storage plugin's disposer calls `backend.close()`, which closed every open unit under a still-draining domain (`packages/storage/storage-json/src/index.ts`), and the package-level repros missed D because the in-memory conformance backend never closed its units.

The fix is a DSH-wide contract with a bounded scope: `Domain.deferClose(settled)` (`packages/storage/storage-domain/src/domain.ts`) lets an owner register a settlement that **infrastructure-initiated** closes await — the facility `closeAll` and, via the `DomainImpl` `onDeferral` hook, the routed backend's `close()`. The owner's own `close()` is never deferred, so a deferral can never deadlock disposal; the settlement is bounded by the process-shutdown grace. `StorageBackend.deferClose?(settled)` (`packages/storage/storage/src/backend.ts`) is optional for a backend whose close never touches open units but required for kv backends by the conformance suite (`packages/storage/storage/tests/contract.ts`); json and sqlite await deferrals before closing units, and the json close is run-once so a concurrent second `close()` cannot close units while the first still waits. The projection cache and message feedback each register their drain settlement and settle it in `finally`; the cache's writes run on a per-session chain (`queueWrite`) with the registration-boundary cut taken eagerly, which closes B and C. Verification: a deterministic facility-unmount repro in `cache.spec.ts` (reverting A fails it), storage-domain deferral contract tests, and the E2E rename → clean shutdown → restart → cold-list title assertion added to the parity suite.

**Finding 2 — stage the inspect manifest until the connection is real.** The first inspect-manifest sync could run before the `connection` the gateway resolves before every sync is active; the attempt failed benignly and the first `connection/reset` re-published anyway. The registry (`packages/extensions/cordis-client-runner/src/client/inspect-registry.ts`) now stages un-armed: registrations stage providers locally until `arm()`, and the runner arms at the first `connection/reset` — the readiness seam, since the client runtime activates only once `connection` resolves and emits a reset per (re-)established generation. A runner that applies after that reset (late entry, HMR) probes the same strict `ctx.get('connection')` the gateway checks, so the probe can never pass while a sync would still fail it. The transient is gone and the parity suite's cold-restart console gate is fully strict.

**Finding 3 — channel replacement is safe; no fix required.** The renderer transport addresses operations by `crypto.randomUUID()`, and a new client silently drops frames for unknown ids, so stale in-flight responses from a replaced channel cannot be misattributed (`apps/desktop/src/renderer/transport.ts`); `RuntimeTransport.onMessage`/`onClose` are single-slot replacements, so no listener accumulates; the product flow never replaces a channel with a live old client (a window tears down its port before any re-open, and the app starts only when no live app exists); and when the port closes the broker's `closeChannel()` reaches the child, whose transport-runtime disposer aborts every in-flight operation. Recorded in `apps/desktop/docs/upstream-contract.md` instead of patched.

**The correctness suite.** `apps/desktop/tests/dsh-event-correctness.spec.ts` (5) drives the built app — real Electron, real desktop-runtime, real pinned composition — against a scripted deterministic SSE provider on the `DEEPSEEK_BASE_URL` seam (step = tool-result count after the prompt marker; a single response carries text deltas plus a trailing tool call for interleaving; the `max_tokens: 64` automatic-title call gets a neutral title). It self-skips without the built artifacts and fails on any renderer `console.error` or page error. The five properties: (1) **burst fold** — text and tool steps in one turn keep exact rendered order and multiplicity, the log keeps every `tool/call` (no coalescing), and the durable sequence order (text deltas, tool calls, tool results, `turn/end`) matches the render order; (2) **cancelled run** — stop after the first chunk: transcript and durable log agree token for token, the tail after the cut is neither rendered nor durable, and a terminal `turn/end { reason: { kind: 'aborted' } }` exists; (3) **renderer reload mid-stream** — the reload detaches the client without cancelling the run: the turn completes in the runtime, every chunk is durable exactly once, the reconnected client folds the full text (no detach-time snapshot), and no event type the scenario cannot explain appears in the durable gap; (4) **pending approval across a reload** — a Read-Only workspace-write escalation survives the reload still answerable, answering completes the turn, and the `tool/call` → `approval/asked` (by `callId`) → `approval/decided` (by `id`) chain is durable in order; (5) **pending question across a reload** — an `ask_user_question` survives the reload still answerable, answering completes the turn.

## Facts the stage settled

- **The durable `assistant/chunk` records are the streaming protocol itself** — `block-start` / `text-delta` / `block-end` / `usage` / `finish`. A `block-end` repeats the block's full text, so per-chunk correctness must be measured on the `text-delta` records, not substrings of the log (a substring count double-counts).
- **Every prompt is durably spliced**: an `agent/inbox/spliced` inserts the user message into the next-turn inbox and a second splices it out at turn start.
- **A renderer reload detaches without cancelling**: the turn keeps executing in the runtime and completes; pending approvals and questions are runtime state and survive the reload answerable.
- `approval/asked` carries `{ id, toolName, callId, reason }`; the escalated tool's arguments live in the `tool/call` record. A user stop ends the turn `{ reason: { kind: 'aborted', reason: { kind: 'user' } } }`; a completed turn ends `{ reason: { kind: 'completed' } }`.
- `session.list` rows carry the projection baseline (`projections: { asOfSeq, values }`), the cold list's title source.
- **Cordis teardown is parallel** (`Fiber._unload` = `Promise.all` over disposers): any owner whose drain outlives its own `close()` must register a deferral at every close point that can out-race it — the facility and the backend, not just the owner.
- The automatic-title call is a chat completion with `max_tokens: 64`; scripted providers must special-case it or the turn body gets a title.
- `expect.poll` requires a test context — helpers that also run in `beforeAll` must poll plainly.

## Consequences

- Stage 8 exit criterion met: the three Stage 6 findings are resolved at DSH seams with no carrier changes; the pinned-source delta is the shared U1–U3 set (upstream-contract.md), M1–M3 remain the complete Desktop-enablement set, and the correctness suite proves the event-preservation properties end to end.
- Full desktop suite: 152 (147 baseline + 5 event correctness).
- The deferral contract is now load-bearing DSH API: any future owner that drains on disposal must register its settlement, and any kv backend whose `close()` touches open units must implement `deferClose` (the conformance suite enforces both).
- The storage-json run-once close removed a latent concurrent-close asymmetry (a second `close()` could close units while the first still awaited deferrals) that affected every consumer, not just Desktop.
- The parity gate's console check is fully strict again — no special cases.

## Alternatives considered

- Desktop-side workaround for Finding 1 (e.g. forcing a projection write before the renderer shuts down) — rejected: the carrier-only rule, and the race is DSH's; `dsh web`'s tab close has the same exposure.
- Retrying the cache's final put after `StorageError: unit … is closed` — rejected: the unit is closed for good; a retry papers over the missing close-ordering contract and the failure mode (lost title) is data loss, not a transient.
- Deferring the backend close unconditionally (always wait for in-flight domain drains) — rejected: a backend cannot see domain ownership; the deferral must be registered by the owner whose drain is in flight, and it must not apply to the owner's own `close()`.
- Arming the inspect registry on a `connection`-resolved event instead of the first `connection/reset` — rejected: no such event exists; the reset is the generation the runtime emits for every (re-)established connection, and it is the one the runner already observes.
- Aborting in-flight operations on transport close (making a renderer reload cancel the run) — rejected: reload is a client-side event; the pinned semantics keep the run alive in the runtime, and the fold-from-log property (test 3) is the correct guarantee.
