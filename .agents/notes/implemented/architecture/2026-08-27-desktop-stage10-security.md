# Agent Note: desktop stage 10 — security hardening: bounded wires, pinned surface, justified CSP

Status: implemented

English | [中文](2026-08-27-desktop-stage10-security.zh.md)

## Problem

Stage 10 (SPEC §24) is the dedicated security-hardening pass across the Electron renderer/preload/main/runtime boundaries. The stage 1–9 builds were built to work, and worked: sandboxed renderer, private `dsh-app://` protocol, generic fetch/stream transport, closed native channel, trusted-IPC sender checks. What the stages had not done was a threat-model pass: which trust boundaries exist, where a compromised peer (a renderer tab under XSS, a malicious document the client renders, a hostile runtime child) can force unbounded work, and whether every Electron surface is pinned by choice instead of by Electron default.

## Decision

**The hardening is entirely carrier-side; the pinned-source delta is untouched.** M1–M3 and U1–U3 remain the complete modification sets. DSH stays authoritative for sandboxing, approvals, tools, model, credentials, and sessions; the desktop layer adds no second policy system.

**The threat model: six boundaries.** A — untrusted content into the renderer (CSP + sandbox + webSecurity bound its effect; the pinned React tree's rendering correctness is pinned-source territory); B — renderer → preload → main (closed six-method bridge; `isTrustedIpcSender` on every renderer→main channel; the stage's main gap: the preload installed into *every* frame); C — renderer → MessagePort → dumb broker → runtime (wire-gated at both edges, 64 KiB frame bound, credit windows; the stage's gaps: unbounded *metadata* and unbounded *concurrent operations*); D — runtime → native channel → main (closed method set, bounded paths/diagnostics; the gaps: unbounded request ids, unbounded response path); E — main → OS (`shell.openExternal` http(s)-validated; `path.open` structurally validated path strings that `shell.openPath` never interprets as URLs); F — runtime/DSH → workspace/tools/subprocesses (DSH's own sandbox and approvals; the desktop env curation — an allowlist, not a passthrough — verified unchanged).

**Every gap the audit found is a wire-trust bound, not a new policy.**

- **Transport metadata bounds** (`apps/desktop-runtime/src/transport.ts`): `parseTransportMessage` — the shared wire boundary of all three edges — now bounds every metadata field: ids ≤512, urls ≤8192, methods ≤16, header count ≤256 (name ≤256 / value ≤8192), status 0..999, status-text ≤256, error codes ≤64, messages ≤1024, reasons ≤256. The values are Web/HTTP norms (request-line and header-buffer sizes) and sit far above the pinned client's real traffic (UUID ids, short API urls), so a compromised renderer can no longer force an arbitrary allocation across the IPC with one cheap frame; an over-bound field is a protocol refusal.
- **Concurrent-operation cap** (`apps/desktop-runtime/src/transport-runtime.ts`): the adapter's in-flight map (fetches + streams) is capped at `TRANSPORT_MAX_CONCURRENT_OPERATIONS = 128`. The bound is a memory bound, not a throughput bound: a `stream.open` is a live in-process carrier fetch for the stream's whole lifetime, and a half-open `fetch.open` that never ends its body stays in the map — an uncapped map let a peer hold an unbounded set of carrier operations open. An over-bound open is refused per operation with the new `too-many-requests` transport code (a stream open gets its `stream.open.ack` refusal with no state of its own); the peer's live operations run to their terminals. 128 is far above the client's ordinary concurrency (single-digit RPCs plus its two event streams).
- **Native channel bounds** (`apps/desktop-runtime/src/native.ts`): request ids take a 512-character bound in all four parsers, and a success response's chooser path takes the same structural check as a request path (non-empty, NUL-free, ≤32768). The operator-cancel form (`path: null`) still parses — a first draft of the fix dropped the field and broke the settle-into-null, caught by the bridge round-trip test.
- **Electron surface pinned, not default-reliant** (`apps/desktop/src/main/window.ts`, `security.ts`, `src/preload/index.cjs`): the BrowserWindow now carries `webviewTag: false` explicitly (a future Electron default change cannot silently re-enable embedding) and `devTools: !app.isPackaged` (packaged builds deny the DevTools API itself, so no menu item, accelerator, or page script can open it). The session installs *both* the permission-request and the permission-check handler as deny-all — the request handler answers prompts, the check handler covers the paths Electron consults without prompting. The preload installs the closed bridge in the main frame only (a top-level `window.top !== window.self` guard before the `electron` require); the main-side sender check still refuses subframe IPC independently, so neither half is the single line of defense.
- **The private protocol closes the decode gap** (`apps/desktop/src/main/protocol.ts`): `decodePathname` rejects a NUL byte in the *decoded* form, not only the encoded one — `%00` decoded to a NUL that the old pre-check could not see. The traversal, host, and symlink checks were already complete and are re-pinned by tests.
- **The boot-graph publication is bound-checked at the wire** (`apps/desktop/src/main/runtime.ts`): `parseBootGraphMessage` (now exported so the boundary is testable directly) drops an over-bound child publication whole — script ≤1 MiB, lists ≤256 items, ids/urls ≤8192, revisions ≤128 — and the generation simply reports no boot artifacts.

**The CSP verdict: `unsafe-eval` is pinned-source-required and stays, with the exact source named.** The renderer seeds `@deepseek-ai/cordis` as a platform module (`packages/client/web/src/platform.ts:11`); the pinned loader's config-expression evaluator is a *module-scope* `new Function('ctx', 'expr', …)` in `vendor/loader/src/config/utils.ts:4` (vendor pin `b150a551`), and it is present in the built renderer bundle — it executes when the module is *imported*, not when a `!!js` expression is evaluated, so the requirement is load-time and no desktop code can avoid it without modifying the pinned source. The runtime smoke's tree-mount wait (`apps/desktop/tests/shell.spec.ts`) is the standing boot proof: without `unsafe-eval`, the module evaluation throws, `__DSH_BOOT__` and the tree never appear, and the test times out. `blob:` is the carrier's classic-script boot path (`evaluateClassicScript` executes the pinned `bootInjections` facade and preload bundles as same-origin blob URLs), and `style-src 'unsafe-inline'` is required by the pinned tree's inline style attributes (the AppFrame `grid-template-columns` the command bridge's frame probe targets). The smoke asserts the exact policy string served; the unit test pins the source; editing either requires re-justifying.

**Zero TCP listeners is a structural fact, now pinned by scan.** The desktop composition disables the `webserver`/`web-runtime` rows — the only HTTP listeners in the web profile — and serves through the in-process carrier; the boundary scan now refuses any socket creation in desktop production source (`createServer(`, `new net|http|https.Server`, `.listen(`), strengthening the stage-1 "no HTTP listener" check into "no network listener".

## Final correction: two source-backed compatibility gaps

The hardened policy exposed two legitimate pinned-client behaviors it broke. Both fixes are the narrowest source-proven exceptions; the stage 10 threat model, surface pins, and bounds are untouched.

**`img-src` gains exactly `blob:` — the pinned image-preview path.** The pinned conversation client previews attachment images as `URL.createObjectURL` results rendered as `<img src>`: draft attachments from a `File` (`packages/client/ui-conversation/src/client/service.ts` `browserDraftAttachment`) and historical images from a `Blob` (the same file's `resolveImage`, which falls back to a `data:` URL only on hosts that lack `createObjectURL` — Electron has it, so the blob path is the live one), rendered by `packages/client/ui-attachment` (`ComposerAttachments.tsx`, `MessageImage.tsx` including the lightbox). Under `img-src 'self' data:` both previews die at load. The correction is `img-src 'self' data: blob:` — local object URLs of the app's own origin only: it permits no remote JavaScript, no general remote resource, and no other directive change; the served policy stays pinned to the exact string by the smoke and the hardening suite, and the shell smoke now proves both preview shapes load while a remote image is refused with an `img-src` violation.

**The permission policy is default-deny with one exact exception: the pinned clipboard write.** The pinned helper (`packages/client/ui-primitives/src/clipboard.ts`) prefers `navigator.clipboard.writeText` and, when the browser declines it, reports failure — its `execCommand('copy')` fallback engages only when the async API is *absent*, not when it is *denied* — so the stage 10 deny-all broke every Copy affordance. A deterministic Electron 43 probe on the `dsh-app://127.0.0.1` origin (a secure context by the privileged scheme registration) established the behavior: with no handlers the write lands on the pasteboard; with deny-all handlers `writeText` rejects with `NotAllowedError`; the write consults the permission **request** handler with the exact permission `clipboard-sanitized-write` (a window-type webContents on the app URL) — the check handler is never consulted for the write; `navigator.permissions.query` for that name throws `TypeError`. The correction installs the same default-deny predicate on both hooks, with the single grant: `clipboard-sanitized-write` from a window-type webContents whose main-frame URL is on the app protocol (the check hook additionally requires the exact app origin, because the Chromium capability probes it receives at load time carry an empty origin and URL and are unverifiable). Electron's permission callbacks expose **no requesting frame** — the main-frame restriction is enforced through the window type plus the main-frame URL, and the app renders no subframes (`webviewTag` off, no third-party frames). No other permission is grantable; no Electron clipboard module is exposed to preload or renderer — the DSH helper stays the sole clipboard authority. The standing proof is a real built-app E2E (macOS): one scripted turn renders a code block, the real Copy affordance flips its success feedback, and the pasteboard holds the block's exact text (`apps/desktop/tests/desktop-clipboard-security.spec.ts`).

Both fixes remain desktop security policy: no pinned-source modification, no new `M*`/`U*` entry, and no new preload or native clipboard surface.

## Facts the stage settled

- The `new Function` that forces `unsafe-eval` runs at **module import**, so the CSP requirement is load-time for the pinned tree; it is a property of the vendor pin, not of desktop code.
- `shell.openPath` treats its argument as a file path only — no URL scheme can reach the OS layer through `path.open`; the structural check (non-empty, NUL-free, ≤32768) is the wire half, DSH's authorization is the policy half.
- A half-open transport operation (an open whose body never ends) is what the concurrent-operation cap actually bounds: it is a memory bound on in-flight carrier operations, and credit windows alone do not cover it.
- The session's permission-check handler and request handler are different seams: denying only the request handler leaves the check path Electron's own.
- The renderer's `connect-src 'self'` is load-bearing: provider/API traffic leaves from the runtime child, never from the renderer page.

## Consequences

- Stage 10 exit criteria met with no pinned-source change: M1–M3 and U1–U3 are unchanged, no new `M*`/`U*` entry.
- The desktop security surface is now pinned by source and by test: the BrowserWindow flag set, the exact CSP string, the closed six-method bridge in the main frame only, the default-deny permission policy with the single source-proven clipboard-write exception, the metadata bounds, the operation cap, and the listener-free composition.
- New suites/coverage: `apps/desktop/tests/desktop-security-hardening.spec.ts` (7: preload main-frame guard + closed surface via CJS evaluation, boot-graph bounds, CSP pin, BrowserWindow flag pin), `apps/desktop/tests/desktop-clipboard-security.spec.ts` (the real built-app Copy integration, macOS) plus the extended `transport.spec.ts` (26), `native-protocol.spec.ts`, `protocol.spec.ts`, `security.spec.ts` (the permission policy's allow/deny matrix), `boundary.spec.ts`, and `shell.spec.ts` (sandbox observables, closed bridge surface, `HTMLWebViewElement` absence, exact served CSP, tree-mount boot proof, blob image previews under the pinned CSP).
- D4 (the Windows job object with KILL_ON_JOB_CLOSE) remains the standing stage 11 packaging item, as does everything else packaging-level (signing, notarization, updater, Electron Fuse).

## Alternatives considered

- Removing `unsafe-eval` and patching the pinned loader to lazy-evaluate — rejected: it is a pinned-source modification for a desktop policy need, and the evaluator is shared with `dsh web`'s config loading; the stage's rule is that a desktop need never edits the pin.
- A CSP `script-src` hash or nonce for the classic-script boot artifacts instead of `blob:` — rejected: the facade and preload bundle bytes are runtime-published (the boot graph arrives over the child IPC), so no static hash can cover them; a same-origin `blob:` URL is the minimal grant that keeps the pinned classic-script semantics.
- Bounding transport metadata by a total-message-size limit instead of per-field bounds — rejected: there is no cheap way to measure a structured-cloned envelope's size at the edge, and per-field bounds at the shared parser cover all three edges in one place with Web-norm values.
- A per-stream or per-fetch cap instead of a combined in-flight-operation cap — rejected: the threat is the sum of live carrier operations, and a single combined bound is the smallest sufficient one (128 covers both primitives with wide margin over real client concurrency).
- A packaged-build E2E asserting `devTools` denial — deferred: the packaged binary is stage 11's artifact; the flag is pinned in source by the unit test and the development-mode path is exercised by the smoke.
- Failing the whole boot-graph message on an over-bound *entry* but still serving a truncated graph — rejected: a partially trusted boot graph is a worse contract than no graph; the drop-whole form keeps "no artifacts" the only failure shape.
