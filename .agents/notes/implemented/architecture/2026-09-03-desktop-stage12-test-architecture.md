# Agent Note: desktop stage 12 — four-layer test architecture, canonical and packaged E2E, migration and upstream-observation safety nets

Status: implemented

English | [中文](2026-09-03-desktop-stage12-test-architecture.zh.md)

## Problem

Stages 1–11 delivered a working, hardened, self-contained, per-platform packaged Electron app. But its test estate was organized around *development surfaces and per-stage proofs*, not a standing regression safety net for the release. Before the next release — and before the dedicated upstream re-pin — the desktop needed five things that did not exist as first-class, maintainable infrastructure: a **layering that localizes a failure to its tier** (unit / real DSH runtime / desktop integration / end-to-end); a **canonical fresh-profile user journey** that is the single "does the real user flow work" test; **proof that the packaged/distributable unit actually runs the workflow** rather than only the development build; **migration safety** for a user's persisted data across a release upgrade; and a **safe, non-blocking way to watch upstream drift** without re-pinning or breaking the release. Required lanes also had to **fail loudly** instead of self-skipping a test they are supposed to run. Stage 12 (SPEC §29–30; §31's boundary tests pre-exist) is the test-architecture pass.

## Decision

**Four layers, each localizing to its tier; each self-skips on a missing environmental precondition and fails loud on a required lane.** **A — unit** is the existing keyless package/unit suite (unchanged). **B — the real DSH runtime with no Electron** is new: `apps/desktop-runtime/tests/runtime-journey.spec.ts` boots the built `dist/index.js` under the pinned DSH (the `DSH_DESKTOP=1` host plane, no web-server fallback), and drives a normal user turn end to end over the *same fork-IPC transport the desktop broker uses* — `session.create` at a fresh cwd → `session.prompt` → the stream surfacing onto the live event mux (the SSE bytes reassembled from `stream.frame`s) → `session.cancel` mid-turn (the final chunk must never arrive; the turn settles `running:false`) → `session.history` replay → clean `runtime.shutdown` (exit 0). If the agent loop, event log, stream carrier, or persistence breaks, B fails with no window in the picture, so a failure localizes to the runtime tier. **C — desktop integration** is the existing real-renderer-over-the-carrier suites (`dsh-parity`, `dsh-event-correctness`, `dsh-crash-recovery`, `desktop-ux`, `desktop-clipboard-security`), kept untouched. **D — end-to-end** is the canonical fresh-profile journey plus the packaged journey (below).

**Shared support modules end the per-suite provider duplication.** Before Stage 12 the deterministic model and the UI primitives were re-inlined in every desktop suite. `apps/desktop/tests/support/deterministic-provider.ts` is now the single scripted loopback model (a turn is a `text`/`tool`/`text-tool`/`fail` step list, routed by a marker in the prompt text plus the tool-result count, an ephemeral `127.0.0.1` port, and the `max_tokens === 64` auto-title call answered with a neutral title so it never consumes a turn). `apps/desktop/tests/support/electron-world.ts` is the single set of UI + persistence primitives the suites drive the *real* renderer with: the transport `rpc` (the shipped `__DSH_TRANSPORT__` fetch carrier, never a backdoor), the composer/sidebar/menu/first-run/access-mode affordances, a version-2 `seedWorkspaceRegistry`, the multi-frame zstd session-log decoder, and the durable-title poll. B imports the provider and the skip helper cross-package (consistent with its existing cross-package provider import); C and D import the world. No working suite was rewritten for aesthetics; the shared modules only deleted duplication.

**The canonical user journey (D) is fresh-profile and picker-driven.** `apps/desktop/tests/dsh-user-journey.spec.ts` starts from an **empty** `DSH_HOME` (no seeded registry), adds the first workspace through the **real native picker path** (the `File ▸ Open Workspace…` menu item, with the `dialog.showOpenDialog` seam standing in for the OS click only — the DSH picker seat, native channel, and main capability all stay real), and then runs the whole journey against the pinned DSH: an incremental stream (the partial text must paint *before* the final text), the bash tool rendered in the conversation *and* the trajectory with its world state verified on disk, an approval (switch to Read Only → Allow once → the escalated command runs), an ask-user question (radio + Submit), `Stop generating` on a running turn, a rename that persists a durable `user`-source title, the settings/Models surface, and a **clean quit + relaunch that restores the session** — the projection title on the cold list and the tool/approval/question rounds replayed. It is the single canonical "does the real user flow work" test; the per-stage C suites keep their focused coverage.

**The packaged journey (D) drives the release binary over CDP, because the fused binary has no Node inspector.** `apps/desktop/tests/packaged-user-journey.spec.ts` extracts the release archive **outside the repository** to a temp location, launches the extracted binary with `--remote-debugging-port=0` (the port read from the binary's own stderr) and a constrained `PATH`, and attaches with Playwright `chromium.connectOverCDP` — **not** `_electron.launch`, which hangs at the inspector handshake on a binary whose `EnableNodeCliInspectArguments` fuse is off (the same fact that forced the smoke's CDP seam). It proves the release-unit concerns the dev journey cannot: `app.isPackaged === true`; the runtime `ready` under the **bundled** Node with the artifact's **pinned** DSH version; a basic stream + tool workflow with world state; a **clean quit through the app's own termination path + a reopen that restores the session** (the smoke only ever SIGKILLs); and that the archive is `sha256`-valid against its sidecar and reproducibly extractable. `isPackaged` and the runtime facts come from the env-gated, read-only `DSH_DESKTOP_SMOKE` report channel — the same seam the per-platform CI smoke uses, inert without the flag — while the workflow itself is pure UI (composer, transport, durable logs).

**The per-platform packaged smoke gains an explicit no-node proof.** `apps/desktop/scripts/smoke-packaged-app.ts` now asserts, before launch, that the constrained `PATH` it runs the app under resolves **none** of `node`/`npm`/`pnpm`/`dsh` (each probed in a child spawned under that `PATH`), so "the packaged runtime runs the bundled Node" is an executed fact rather than an inference from "the app booted".

**Required lanes fail loudly; local and headless skips stay clean.** A shared `e2eRequired`/`skipUnless` (in `electron-world.ts`; inlined in the cross-package B spec, which already imports the shared support) implements the semantics: when a CI lane sets `DSH_DESKTOP_E2E_REQUIRED=1`, a missing precondition (no GUI, no built runtime, no built archive) is a hard `beforeAll` **failure**, never a skip; without the flag the suite self-skips. This closes the vacuous-pass hole where a misconfigured required lane (e.g. a Linux lane with no `DISPLAY`) would silently skip the very test it exists to run and report green.

**Migration safety is a reusable harness with an honest pre-release stand-in.** `apps/desktop/tests/support/migration.ts` + `migration.spec.ts`: `createMigrationFixture` generates a realistic profile through the current app (a seeded workspace, a streamed turn, a tool turn that writes a file, and a user-set durable title), and `verifyMigratedData` boots a **fresh** instance at that profile and asserts the workspace is listed, the session survives, its durable title is on the cold list, the first-run acknowledgement persisted, and reopening replays the recorded content. Because **no prior released artifact exists yet**, Phase A is a same-format stand-in for a real prior release's data; the harness's `verifyMigratedData(userData, …)` is what a true cross-artifact A→B check will run once a prior release ships — point it at that release's user-data directory. The invariant proven now is the one a future A→B must preserve: the current release's persisted data is intact under a fresh instance of itself.

**The upstream observation track is a safe, non-authoritative drift probe plus a readiness report.** `scripts/upstream-observation.ts` + `.github/workflows/upstream-observation.yml` (scheduled weekly and on manual dispatch **only** — never on `pull_request` or `push`; `contents: read`) fetches upstream `master` into `FETCH_HEAD`, reports drift (commits ahead of the pin, pin reachability, newer release tags, changed top-level paths), and runs the desktop delta (pin → fork head) through `git apply --check` in a **throwaway worktree** that is removed before exit. It reports `upstream-compatible` / `upstream-needs-adaptation` / `upstream-unchanged` and **always exits 0** (a finding is a report, not a build failure); it never merges, never writes a tag, and never changes the pinned SHA in `UPSTREAM.md`. The report carries the SPEC §30 six-step re-pin checklist. The current observation is **`upstream-needs-adaptation`**: upstream has advanced 1834 commits since the pin and changed files the desktop delta touches, so the delta does not apply cleanly — which is exactly the signal a re-pin is not ready to run blindly.

## Facts the stage settled

- The fused release binary has no Node inspector but honors `--remote-debugging-port=0`; Playwright `chromium.connectOverCDP` against that endpoint is the working drive seam, and `_electron.launch` (which adds `--inspect`) hangs at the handshake. The app's window is the `dsh-app://` page target in the CDP list.
- The renderer is served from `dsh-app://` in **both** dev and packaged, so the page origin cannot distinguish the two; `app.isPackaged` and the runtime facts are only readable through the env-gated `DSH_DESKTOP_SMOKE` report channel (the CI smoke's seam, inert without the flag).
- A fresh DSH_HOME has no workspace and the composer is not editable until one is added; the canonical journey therefore *must* drive the picker (the seeded-registry path is the parity/smoke alternative, not the canonical one).
- The default session access mode runs `bash` without an approval; the approval path is triggered by switching to Read Only (the canonical approval test does exactly that).
- The runtime child is forked with `DSH_DESKTOP=1`, `DSH_HOME`, and the keyless `DEEPSEEK_API_KEY`/`DEEPSEEK_BASE_URL` (the loopback provider); the event mux is opened over the same fork-IPC transport, with `stream.frame`/`stream.end`/`stream.error` routed to a sink so they do not compete with fetch control messages on the FIFO.
- `git worktree add` prints per-file checkout progress to stderr; an `execFileSync` against it needs a roomy `maxBuffer` or it dies with `ENOBUFS` before the probe runs.
- `git apply --check` reports each failing file as `error: patch failed: <path>:<line>`; the report captures those lines verbatim rather than parsing them into a fragile list.
- The distributable archive is `DeepSeek Harness Desktop-<version>-<platform>-<arch>.zip|.tar.gz` with a `.sha256` sidecar in `sha256sum` format (`<hex>  <name>`); the packaged journey verifies both the digest and a second independent extraction.
- The desktop delta is 45 commits (pin → fork head) touching `apps/desktop`, `apps/desktop-runtime`, `.agents/notes`, and several upstream `packages/` the delta also modifies — which is why it cannot apply cleanly on a master that has advanced 1834 commits.

## Consequences

- Stage 12 exit criteria met with **no pinned-source change**: the pinned DSH stays `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e` (`dsh-v0.1.1-rc.2`). New: `apps/desktop-runtime/tests/runtime-journey.spec.ts`, `apps/desktop/tests/dsh-user-journey.spec.ts`, `apps/desktop/tests/packaged-user-journey.spec.ts`, `apps/desktop/tests/migration.spec.ts`, `apps/desktop/tests/support/{deterministic-provider,electron-world,migration}.ts`, `scripts/upstream-observation.ts`, `.github/workflows/upstream-observation.yml`; extended: `apps/desktop/scripts/smoke-packaged-app.ts` (no-node proof).
- The four layers are the standing regression safety net: A (keyless unit) → B (real runtime, no Electron) → C (real renderer over the carrier) → D (canonical fresh-profile + packaged release-binary journeys). Required lanes run them with `DSH_DESKTOP_E2E_REQUIRED=1`; a broken precondition there is a loud failure.
- The packaged journey and the extended smoke together prove the *release unit* (extracted archive, `app.isPackaged`, bundled Node, workflow, clean quit + reopen, checksum), complementing the per-platform CI smoke that owns the fast boot/security/carrier/crash proof.
- Carried forward, unchanged: the product-owned D4 `KILL_ON_JOB_CLOSE` end-to-end kill drill is **implementation-complete but not behaviorally green** (every available Windows launch context is externally job-contained) — an explicit final-v1 validation obligation; the four upstream self-hosted CI checks remain unavailable on the fork (infrastructure, not product); signing/notarization remain configured-not-executed where credentials are absent.
- The observation track is the standing, non-blocking watch on upstream drift; its current verdict is `upstream-needs-adaptation`. **No re-pin was performed in Stage 12** — the dedicated re-pin (select SHA, adapt, re-run the authoritative suite, manually test, then change `UPSTREAM.md`) is the next task and must run its own full validation.

## Alternatives considered

- Driving the packaged journey with Playwright `_electron.launch` — rejected: it requires the Node inspector the fuse deliberately removes; `connectOverCDP` against the browser DevTools endpoint is the seam an external observer actually has.
- A full cross-merge rebase probe in the observation track — rejected for the standing lane: rebasing a 45-commit delta onto a master that has moved 1834 commits is heavy and fragile, and a broken observation must never read as a broken release; the bounded `git apply --check` gives a safe, real compatibility signal and the readiness report carries the re-pin procedure for when it is run deliberately.
- Seeding the canonical journey's workspace registry instead of driving the picker — rejected: the fresh-profile + real-picker path is the actual first-run user flow and the whole point of the canonical test; seeding is the parity/smoke alternative.
- A true cross-artifact A→B migration test against a real prior release — impossible pre-release (no prior artifact exists); the honest stand-in plus a reusable harness is the correct pre-release state, with the harness ready to point at a real prior profile when one ships.
- Making the observation workflow a required PR check — rejected (SPEC §30): the observation is non-authoritative by design; the authoritative release track is `ci.yml` against the pinned SHA.
